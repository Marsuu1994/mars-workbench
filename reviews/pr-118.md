### 3 · `scripts/specCoverage.ts:293` · bug · [comment](https://github.com/Marsuu1994/mars-workbench/pull/118#discussion_r4596567348)

### 4 · `scripts/specCoverage.ts:25` · bug · [comment](https://github.com/Marsuu1994/mars-workbench/pull/118#discussion_r4596567905)

> **间接跳过的 test 仍然算 holder**
>
> `TEST_CALL` 只按调用本身的 `.skip` / `.todo` 排除。下面三种仍然算作守着 ID：
>
> - `describe.skip` 或 `test.describe.skip` 里的 `it`
> - test 体内 `test.skip(cond)` 之下的 `test.step`
> - 被注释掉的 `// it('MV-4 …')`
>
> 这和 `test/README.md` 的「A skipped test holds nothing」不一致。例子：把整个 `describe('A move')` 改成 `describe.skip`，A4、A6、A7、MV-1、MV-4、R5 都不再运行，`check:spec` 仍然报告全部 held。
>
> 纯文本检查很难完全堵住。最便宜的一步是：文件里出现 `describe.skip` 或被注释掉的 test 调用时直接报错。

**Outcome:** fixed in this PR: comments are stripped before titles are read, and a `describe.skip` fails the check. A step under `test.skip(isMobile)` still counts, on purpose: J3 and J4 each run in one of the two projects, so every such step runs.

### 5 · `scripts/specCoverage.ts:19` · bug · [comment](https://github.com/Marsuu1994/mars-workbench/pull/118#discussion_r4596568456)

> **`UTF-8`、`ISO-8601` 这类标题会被当成 spec ID**（推断：现在没有这样的标题）
>
> ID 的模式是 `[A-Z]+-\d+`，而 `check:spec` 扫描 `src`、`e2e`、`scripts`、`test` 下所有的 test 文件。任何以「大写单词-数字 + 空格」开头的标题都会被当成 spec ID。
>
> 例子：某个无关的 unit test 写了 `it('UTF-8 input is decoded …')`。
>
> - 文件没有 `// Spec:` 注释：报「titles name spec IDs, but it doesn't say which spec」。
> - 文件有 `// Spec:` 注释：报「names UTF-8, which board.md doesn't have」。
>
> 两种情况 CI 都会红，只能改标题绕开。可以只在有 `// Spec:` 注释的文件里读 ID，没有注释的文件不看标题。

**Outcome:** fixed in this PR: titles are read only in files with a `// Spec:` comment, so the "titles name IDs without saying which spec" check is gone; a test in an unmarked file holds nothing, and its item is reported as not held.
