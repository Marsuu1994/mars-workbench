Behaviour (the e2e contract)

  1. No archived projects → no section (as today).
  2. Every visit opens with the section collapsed — unless no project is active, then open (Q1): the header is a button with aria-expanded="false"; the archived rows aren't shown.
  3. The header's name reads Archived and shows how many are archived.
  4. Clicking (or Enter / Space on) the header opens it: aria-expanded="true", every archived row with its Unarchive. Clicking again closes it.
  5. Archiving a project while collapsed only bumps the count; the section stays collapsed.
  6. Unarchive keeps the section open; the project goes back to the active list. Unarchiving the last one removes the section.
  7. Open / closed is page state only: a reload starts from the default again (Q2).

Build notes

  • Header: <button aria-expanded aria-controls> + a panel with id; the panel unmounts when closed (no hidden copy for tests to trip on).
  • Chevron: Heroicons ChevronRightIcon, rotate-90 when open, a short transition.
  • Label: SectionLabel (Projects.List.archived); count: an ICU-free numeral in a quiet Pill.
  • Hover / focus-visible: label and chevron in primary; a focus ring on the button.
  • The open state lives in ProjectList (useState, initialised from “no active project” on mount) or a small ArchivedSection beside ArchivedProjectRow.
  • Design Console: the projects scenario's list tab stays collapsed; a new tab opens it with a play step clicking the header.

Decided (owner, 2026-10-31)

  • Q1 Every project archived (“No active projects” on the right): the section starts open, since the empty state says “unarchive one”.
  • Q2 Open / closed is not remembered across visits.
