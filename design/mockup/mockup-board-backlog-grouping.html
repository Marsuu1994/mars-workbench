修订 2026-11-18 · 列表做完以后的空状态

空状态要给出下一步

Apple HIG › Writing
HIG 把"做完的 to-do list"列为一种空状态，说空状态通常是暂时的，要告诉用户接下来能做什么，可能的话给一个按钮或链接（HIG）。
→ 给出下一步，但只用文字。Apple 默认会推一个动作；我们的 2.3 要求两个选择分量一样，所以不放按钮。

收工：入口留着，换成完成的状态

Sunsama daily shutdown
做完 shutdown 显示 "Shutdown completed!" 和一句用户自己选的话（鼓励、自定义、或者不显示）；导航里的 Shutdown 不消失，而是带上一个 ✓（help）。
→ 最接近的先例：平静地说这一段做完了，入口留着、换个状态。我们留着入口，badge 显示 0。

"You're all caught up"，不推任何动作

Linear inbox（二手来源）
一句话加一张随机换的小插图，没有按钮（pivotlog）。
说清楚做完了，但没说接下来能做什么；我们的第二行补上这一点。

Badge 到 0 就隐藏

Things 3
Today 的 badge 只在里面有 to-do 时出现（Things support）。查过的产品里没有一个在 badge 上显示 0。
→ 我们是有意不同：backlog 的入口两端一致、永远找得到，打开就是这个终点线。
第 2 轮 · 进度标记旁的分数，以及封顶计数

Visible "x of y"：只在有意义时显示

Primer · Carbon · WCAG guidance
各家 design system 都要求 progress bar 必须有 accessible name，但屏幕上显示数值是可选的：数值已经以文字形式出现在旁边时，Primer 不再加单独的 label（Primer）；Carbon 只在上下文已经清楚时才省略可见 label（Carbon）；只有数字、没有 name 是不合格的写法（getwcag）。
→ 定了：屏幕上不显示，dots 和 path 就是进度；分数作为它们的 accessible name（aria-valuetext "1 of 3 done this week"）。

Capped badges

MUI · Flutter · Braze
计数 badge 用 "+" 封顶：MUI 默认 99+（MUI），Flutter 的 Material badge 是 999+。Braze 的 iOS 指南提到，badge 数超过两位数后用户就不再看了（Braze）。
→ 8+。那些上限是为了宽度；我们的上限是为了这一周给人的感觉，所以低得多。这是有意的产品选择，不是惯例。展开 panel 仍能看到全部。

Sequential project 只显示第一个可做的 action（Omni manual）；Sunsama 的重复任务只显示下一个 instance（help）。

空的 backlog · 修订 2026-11-18 · decided 2026-11-18 · 入口留着，计数 0

Backlog 拉空，说明这周排的 habit 和 step 都已经上了 board。现在的产品里这时 mobile 的 pill 直接消失，desktop 的 strip 显示 0、panel 里一行灰字。改成：两端入口都留着，badge 显示 0（strip、pill、panel 和 sheet 的 header 都一样）；打开后是一个虚线框：标题 cheer 一下（Everything's on deck!，强反馈），下面两句完整的话、不加标点——第一句说事实，第二句说下一步。框里只有文字，不放按钮：改计划再加，或者这周就到这，分量一样（Principle 2.3）。拖拽提示那一行在空的时候也去掉（1.1）。

事实那句只说 backlog 知道的：都上 board 了，不说做完了——情况 1（周一全拉上来，Todo 还一堆）和情况 2（一周都做完）都属实。
