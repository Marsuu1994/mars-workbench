The badge counts staged tasks — every habit instance, every step on this week, every one-off — not groups. Up to 8 it shows the number; past 8 it shows 8+, so a heavy week never opens on a 16 or a 20. Round 2 · a fraction beside a progress mark, and capped counts

Visible "x of y" — only when it adds meaning

Primer · Carbon · WCAG guidance
Design systems agree a progress bar needs an accessible name either way, but treat a visible value as optional: Primer skips a separate label when the value already shows as text next to it (Primer); Carbon drops the visible label only where the context is already clear (Carbon); a bare number without a name is the failure case (getwcag).
→ Decided: shown on both kinds, and the same text as the accessible name (aria-valuetext "1 of 3 done this week").

Capped badges

MUI · Flutter · Braze
Count badges cap with a "+": MUI defaults to 99+ (MUI), Flutter's Material badge to 999+. Braze's iOS guidance notes people stop reading badge counts once they pass double digits (Braze).
→ 8+. Those caps exist for width; ours is about how the week feels, so it sits much lower — a deliberate product choice, not a convention. The panel itself still shows everything.
