Week wrap-up — 没有 active plan 时迎面而来的那一屏

Fixture：W45 · Mon Nov 2 – Sun Nov 8 2026，wrap-up 发生在 Sun Nov 8 晚。用户必须有 active plan；没有的时候，打开 app 看到的不是空 board，而是全屏的 上周 summary + 下周 plan（the gate）。周日晚可以提前 wrap up 本周、定下周，但下周的 plan 周一才生效。已定的照画：summary 是 7 格日条 + 每个 habit 一行 dots + Steps done / One-offs done 清单，没有 %、没有 points；新 plan 的主路径是「去 Claude 里规划」，app 内手动三步是第二层；周日 board 有一个 wrap-up 入口，plan 建好之后 board 进入 rest 状态。要 owner 选的三件事并排画在第 4、5、6 屏：summary 和 plan 是一屏还是两步；周日入口是 banner 还是卡片；rest 状态下 board 照常还是更安静。第 7 屏是 research 来源。

Before · 现在：plan 结束后的空 board（EmptyBoard，returning user）

现在 plan 一结束，board 变成一页空状态：一个时钟图标、「Plan period ended」、三个大数字（Completed %、Tasks done、Points earned）和一个「Create New Plan」按钮，跳到另一页的三步表单。它是一个总结给分的画面：大数字和 % 在评判这一周（Principle 6），points 是要去掉的概念，而且它什么都不告诉你——哪天做了什么、哪个 habit 做到了几次，都看不见。按钮把人送去另一页，plan 和 recap 彼此看不见。

After · 桌面：全屏 summary（左）+ 下周 plan（右）；没有 active plan 时它就是 Board 这个 tab

这是一个 gate：没有 active plan 就只看到它。左边是回顾：标题写死边界「Nov 2 – Nov 8 · W45」，第一块是 ① Board 上同一条 7 格日条（lg 尺寸，一周已结束所以没有 today ring）；第二块每个 habit 一行，名字 + 该 habit 这周的 dots（和卡片上的同一个零件，做了填实、没做空心，不写 missed、不配文字）；第三块是做完的 step 和 one-off 清单，一行一个（kind icon + project 名 + 标题 + 哪天做的）。没有合计大数字、没有 %、没有 points、没有「你本可以」——语气是回顾（spike 痛点 4 的 C 形状第 4 条）。右边是下一周：「Starts Mon, Nov 9」，主按钮 Plan with Claude，按钮下一行小字说明它只是「打开 Claude、prompt 已填好」（链接只能预填不能自动发送，见 Research），兜底 Copy prompt，次链接「Plan here instead」展开 app 内的三步（第 3 屏）。「Planned · done, last weeks」默认收起，展开是 W41–W45 和下周草案的个数。周日晚提前 wrap up 和周一早被迫 wrap up 看到的是同一屏：周日 board 上的入口（第 5 屏）点进来是它；周一打开 app、上周 plan 已过期，迎面的也是它。这里画的左右布局是第 4 屏的方案 (a)。

手机 · Before / After 并排

手机上 summary 占满一屏半以内：日条、三行 habit、两组清单；Plan next week 是底部 sticky 的一条（拇指区），往下滚到底就是下周的 Claude 入口（第 4 屏方案 a），所以 CTA 既是「滚下去」也是「跳下去」。Before 的手机版是同一个 EmptyBoard，三个大数字挤在 340 px 里。

解剖 · summary 的三块各说一件事
1 · 日条这周每一天发生了什么`dayStrip(FIX.stripFinal, {todayIndex: -1, size: 'lg'})`——和 ① Board 顶部同一个零件，只是放大、没有今天。一格 = 当天 done / planned 的个数，pips 填实 / 空心。Wed 和 Sat 各一颗空心是没做的 Workout，不是红、不是「missed」。整条的 accessible name 是「This week: 16 of 19 done」，屏幕上不写 16。
2 · habit 行每个 habit 做到了几次名字 + `dots({target, doneSlots})`，Workout 7 颗、LeetCode 4、Read 3。和卡片上的 dots 同一个零件、同一种绿，所以用户不用学新符号。不写 cadence（dots 的颗数已经是 target）、不写 5/7（Principle 1：一个元素一个意思）。
3 · 清单做成的 step 和 one-off卡片缩成一行：kind icon + project 名（mono、kind 色）+ 标题 + 右侧 mono 的星期几。只有做完的；没做完的不在这里出现——它们在 plan 那一侧，作为下周的默认带过去（Smit 2016：未完成的事要有去处）。
0 · 没有的%、points、合计、评语Dai 2018：好一周之后的「reset」会打击动机，所以 summary 不清零、不打分；它把做成的事原样带到下一周的旁边（第 3 屏的四周对比只是个数）。标题写周数和日期，不写「Great week!」这类伪 landmark。
After · 桌面：点了「Plan here instead」，summary 的位置换成页内 stepper；Claude 入口留在右侧

主路径是 Claude，三步是第二层。Claude 的 guide（MCP）本来就是先 recap 上周再和你定下周，所以 Plan with Claude 不需要 app 再复述一遍；按钮只承诺「打开 Claude、prompt 已填好」：桌面开 claude://claude.ai/new?q=…，手机开 https://claude.ai/new?q=…（可能弹 untrusted prompt 确认），所以 Copy prompt 不是可选的兜底。prompt 很短——Claude 通过 MCP 自己读数据。手动三步借旧 mockup 的 Plan this week，按新风格重画：没有 pts 合计、没有 size；页内 stepper 不是 modal（NN/g：wizard 只给生手 / 低频流程，但这是表单，保留三段步骤条、按钮写「Next: projects」而不是 Next、每步页首重复上一步选了几个、退出保留草稿）。每步预填上周（Sunsama「Continue N objectives」、Madrian & Shea 默认效应）：habits 默认全部延续、显示 cadence「Daily / 4× / week」和上周的 dots、页头「3 of 3 habits」；projects 默认带上没做完的 step（carried）再加下一步、「2 of 4 projects」，stepper 定排几步，列出的就是会进 backlog 的 step；one-offs 从 matrix 勾，carried 和 Do first 预选。最后一个按钮「Create plan · starts Mon, Nov 9」。右侧的「Planned · done, last weeks」是为了让过时的默认看得见（默认会粘住：Madrian & Shea 80% 两年不改）——下周草案 19 planned，旁边是最近五周的 done / planned，个数，不是 %。试试勾掉一个 habit、加减 step：草案的个数跟着变。

After · 手机：Claude 入口一屏；三步各一屏，底部 sticky 的 Next

手机上 Next week 自己占一屏（summary 滚到底，或从 sticky 的 Plan next week 跳到）：第一层只有 Plan with Claude、Copy prompt 和「Plan here instead」。点了它才进三步，每步一屏、底部 sticky 的「Next: …」，步骤条在顶。第 3 步的「Create plan」就是出 gate 的那一下。

并排画 1 · summary 和新 plan：一屏上下 / 左右排，还是分两步？

三条 research 线在这里一致：NN/g 把高频、熟悉、只读的流程排除在 wizard 之外；Sunsama 自带「Combine review and planning」开关，合并后 review 是 planning 的第一段；Apple 的周总结末尾直接调下周目标；Dai 2018 要求好成绩被带进下周；Heylighen & Vidal：review 的终点是「下周总览」。(a) 把 summary 和 plan 放在一屏，桌面左右、手机上下 + sticky CTA，看 plan 的时候 summary 还在眼前。(b) 每屏元素更少，但看 plan 时看不见 summary，多一次点击。手机上 (a) 要控制 summary 在一屏半内，否则极长页会被放弃（NN/g）。

并排画 2 · 周日的 wrap-up 入口：banner 还是一张卡片？（Sun Nov 8 · 18:20 · 有 active plan、还没 wrap up）

板上是 ① 的 After board（today ring + 日条，Todo / Done 两列），周日傍晚：Workout 还在 Todo，Read #3 已经做完。入口只在 周日 18:00 → 周一 plan 生效这段窗口存在，点进去就是第 1 屏的 gate；做完 wrap-up 它自己消失，不需要 dismiss（Live Activities 的「有始有终」）。三条线在这里分歧：products 和 literature 偏 banner（Sunsama 的 auto-prompt 在右上角、Apple / WHOOP 都是 notification——review 是系统送达的，不是用户的工作项），interaction 偏卡片（NN/g banner blindness：页顶、变色、和周围不一样的东西在手机上会被学着跳过；卡片在内容区、拇指区内）。两边都画出来，推荐卡片，理由在各自的 why 里；这一项请 owner 拍板。

并排画 3 · rest 状态：下周 plan 已建好、还在周日（Sun Nov 8 · 21:40）

Wrap-up 做完以后，没做完的东西已经带进下周或 drop 了，所以 Todo 列自然就是空的——rest 不是一个新页面，是同一张 board 的空态（Oura Rest Mode 保留记录项、禁用目标项；Streaks 的 paused task；Apple「Pause rings until Monday」；Todoist Zero 是内容空 + 一句话，没有产品整体 dim）。两边都用日期表达「还没开始」（「starts Mon, Nov 9」），不用 Scheduled / Pending 这类状态词；下周预览是一行虚线框的 muted 文字，不可拖、不像控件（Principle 3）。(a) 和 (b) 的差别只在：Done 日志和日条还能不能照常读。

Research · 其他产品和文献怎么做 weekly review、gate 和 rest

Review 是送达的，不是用户的工作项

Sunsama · Apple Watch · WHOOP
Sunsama 的 weekly review 到点自动 prompt（help）；Apple Watch 每周一通知上周成就，并在同一处调下周目标（Apple）；WHOOP 周一推 Weekly Performance Assessment（摘要）。
→ Mars 的「没 active plan 就迎面给」是最可靠的送达；周日的入口和 ⑤ 的 22:00 推送只是把人提前带到同一屏。

Weekly review 三步，结束按钮叫「Wrap up」

Sunsama
Objectives → body of work → journal，每步可跳、可永久关；第 2 步「body of work… provides a sense of accomplishment」（changelog）。Review 和 planning 默认分开，一个「Combine review and planning」开关合并；planning 第一步是「Continue N objectives」（help）。官方反对提前把每一天排满（changelog）。
→ summary 的清单就是 body of work；plan 每步预填上周；动词用 Wrap up。

周日 / 周一归属

Sunsama · Amazing Marvin
Sunsama：Thu–Sun 做的 weekly planning 算下周，Mon–Wed 算本周（同上两页）。Marvin 把「Do weekly review」做成一个每周的 task（help）。
→ 周日晚建的 plan 周一生效是现成先例；Marvin 是第 5 屏「卡片」方案的先例。

Gate 的先例

Sunsama legacy daily planning
到点 prompt 做 planning；没做 shutdown 就先 review 昨天；下午 3 点之后计划的是明天（help）。评测称它「forces you to confront reality」（Asian Efficiency，旁证）。
→ gate 要一步能出去（主按钮即出口），不带惩罚语气（Deci：reactance）。

Rest 不换页面，是同一张画面被静音

Oura · Streaks · Apple Fitness · Duolingo
Oura Rest Mode 保留记录项、禁用目标项（Oura，摘要）；Streaks Vacation Mode 暂停不清零（Streaks）；Apple「Pause rings until Monday」（旁证 iMore）；Duolingo 的 Weekend Amulet 让周末不算断（Duolingo）。
→ 第 6 屏方案 (a)：日条和 Done 日志照常、Todo 空、一句话 + 下周预览。

Fresh start：紧跟边界的那天

Hennecke & Converse 2017 · Dai & Li 2019 · Beshears 2021
人偏好在 temporal boundary 之后的第一天开始（Batten 摘要）；fresh start 综述 DOI 10.1016/j.copsyc.2018.04.012；把「以后开始」框成 fresh start 不会减少「现在就做」（UCLA Anderson，DOI 10.1016/j.obhdp.2021.06.005）。
→「plan 周一才生效」不是摩擦，是人自己的偏好；plan 上写死「Starts Mon, Nov 9」。

Reset 的双刃剑

Dai 2018
强表现之后的 reset 让动机和继续率下降（UCLA Anderson，DOI 10.1016/j.obhdp.2018.06.002）。
→ summary 不清零、不打分；plan 侧留着最近几周的个数作参照，做成的 step 留在清单里。

未完成的事要有去处

Smit 2016 · Syrek 2017 · Sonnentag & Fritz 2007
给未完成的目标一个计划就能放下（DOI 10.1111/joop.12137）；看见未完成的任务是周末 rumination 的线索（DOI 10.1037/ocp0000031）；psychological detachment 是恢复的核心（DOI 10.1037/1076-8998.12.3.204）。
→ 没做完的 step 和 one-off 作为下周的默认带过去，wrap-up 之后 Todo 列才真的空。

默认即决定，但默认会粘住

Madrian & Shea 2001 · Jachimowicz 2019
默认加入后 80% 两年不改（NBER）；默认效应 meta d = 0.68（DOI 10.1017/S2398063X1800043X）。
→ 三步全部预填上周；旁边放「Planned · done, last weeks」让过时的默认看得见。

Wizard 只给生手；banner 会被跳过；次要信息收起

NN/g
Wizard 不适合高频、熟悉的流程，用时要显示步骤、按钮写明下一步（wizards）；页顶、变色、和周围不一样的东西会被当广告学着跳过（banner blindness）；次要信息渐进展开（progressive disclosure）。
→ 三步是第二层、页内不弹 modal；第 5 屏推荐卡片；四周对比默认收起。

Handoff 到 Claude：只能预填，不能自动发送

Claude support · GitHub
桌面 claude://claude.ai/new?q= 预填 prompt（support）；手机的 claude:// 只覆盖 Code 路由（support）；claude.ai/new?q= 的自动提交 2025-10 停止（issue）；非官方 README（旁证）。
→ 按钮下写「Opens Claude with the prompt filled in」，Copy prompt 必须有。

有始有终的系统提示

Apple HIG · Todoist
Live Activities 在事件结束时自己消失，不用用户 dismiss（HIG）；Todoist Upcoming 用日期表达「还没到」，不用状态词（help）。
→ 周日入口到点出现、wrap-up 后消失；rest 状态用日期而不是 Scheduled / Pending。
给 owner 拍板
  1. 一屏还是两步（第 4 屏）：推荐 (a) 一屏。
  2. 周日入口（第 5 屏）：卡片还是 banner——research 三条线分歧，推荐卡片。
  3. Rest 状态（第 6 屏）：推荐 (a) 照常 + 一句话。
  4. 周日入口几点出现：暂定 18:00（Sunsama 的 weekly review 默认也是周日傍晚）。
  5. 周一的 gate 是否允许「Later」先看 board：建议允许（HIG Modality：全屏 gate 也要有明显出口），但 board 会是空的——出口的文案和位置待定。
  6. 手机上 claude.ai/new?q= 的 untrusted prompt 弹窗能否接受，还是手机只给 Copy prompt。
