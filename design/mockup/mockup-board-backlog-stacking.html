Board · Backlog stacking

In the backlog, a habit's instances collapse into one card, and so do a project's steps. One-offs never stack. The top card is the one a pull takes; a ×n chip and paper lips say how many sit behind it. Todo and Done never stack. Example week: Weekly review 3× / week with two instances still staged, Spanish A2 Units 3 and 4 put on the week.

Rules

KindStacks withTop card (what a pull takes)The card shows
Habit Every staged instance of the same habit (same template). Daily instances only ever come from today — yesterday's expire — so there is never a cross-day stack. The lowest instance (its dot ringed) The habit's face; its week dots ring the top instance and dash the ones queued behind it
Project step Every staged step of the same project The earliest step in the project's order The top step's face (3/6), a Next: … line naming the step behind it, the path ringing the top segment and dashing the queued ones
One-off Never stacks — Its own card. (A one-off tracked onto the week lands in Todo, so in practice none reach the backlog.)
  • A stack of one is a plain card — no chip, no lips. ×2 shows one lip, ×3 and up two.
  • The backlog's counts (desktop strip and header, mobile pill and header) still count tasks, not stacks.
  • No schema or server change: a pull is still one BACKLOG → TODO update on the top card's task.
  • Stacks keep the backlog's existing order (daily, then weekly, then projects; each group where its earliest task sorts).
