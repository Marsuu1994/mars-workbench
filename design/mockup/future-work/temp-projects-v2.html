Reference the two modals this reuses — today

Same shell, same field order, same size picker (effort hint, split warning for L / XL), same footer. The project modals change only the banner, the placeholders and — for a project — drop Size, which belongs to steps.

After plan › projects · try it — New project, + Add step, ✎, + This week

Everything here is a modal or a one-tap action; there is no inline editing. Done steps are locked (no ✎) because they carry points history. A step still in the backlog can be taken off the week (×); a started one only leaves through Edit Plan. With no active plan, + This week is disabled with the matrix's no-plan hint.

After the four project modals

1One shell

All four are the TaskModal shell (centred on desktop, a bottom sheet on mobile): header with the close ×, a form, a footer with Cancel and the primary action on the right. Destructive actions sit on the left of the footer, only in edit mode.

2Project fields

Title (required) and Goal (optional, "what does done look like?"). No size — a project's size is the sum of its steps. Edit Project adds Archive: unfinished steps leave the week and the project moves to Archived; done steps keep their plan.

3Step fields

The template modal's fields: Title (required), Description (a link, notes, what done looks like) and Size with the effort hint and the L / XL split warning. The header says which project and which step number it becomes. Edit Step adds Delete step (not-done steps only).

4One step at a time

The modal closes after Add step, like Add Priority Task. Entering a whole syllabus is what Claude does over MCP (create_project with ordered steps); the UI is for adding, fixing and reordering.
